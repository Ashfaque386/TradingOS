## Evidence standard & terminology

Findings use the requested five‑field form (Finding / Expected / Actual / Evidence / Impact / Severity / Recommendation). Labels are kept distinct:

- **Requirement** — something a design doc mandates.
- **Observation** — a neutral fact about the implementation.
- **Bug** — violates a documented requirement, errors, or produces incorrect behaviour.
- **Architectural Risk** — works today but threatens reliability/security/scale.
- **Recommendation** — proposed change; not itself a requirement.

Distinctions enforced throughout: **LLM call ≠ Agent ≠ Tool ≠ Workflow ≠ Orchestrator ≠ Automation**.

# 1. Executive Summary

TradingOS is **not** an "illusion of functionality" system. The agent layer is genuinely implemented: a real LangGraph state machine (`src/agents/graph.py`) compiles **13 pipeline nodes**, each backed by a real function that makes real multi‑provider LLM calls (`src/agents/llm_router.py` + `routing.yaml`) or real deterministic execution (sandboxed vectorbt backtests, hardcoded risk/compliance checks). Runs are persisted (`AgentRun`/`AgentLog`), streamed to the UI over WebSocket, and written to an immutable SHA‑256 hash‑chained audit log. There are **1,072 backend test functions** across 180 test files and **13 Cypress specs**, and a real CI pipeline. The project also maintains an unusually candid self‑audit (`Phase_14_Master_Development_Roadmap.md`, ~2,300 lines, 65+ releases) and a 26‑sheet ERDTM traceability workbook.

The gap between vision and implementation is therefore **not** "it's all fake" — it is:

1. **The autonomous *research* loop is real but has never completed one unbroken end‑to‑end live run.** Every node is individually proven; a full CEO→Deployment run has been blocked repeatedly by exhausted free LLM credits (documented in REL‑005 exit criteria).
2. **The autonomous *trading* half is deliberately, permanently absent.** By an absolute project constraint, no code path places a real order. This is correct risk posture but means "autonomous trading OS" per the SRS vision is realised for research/backtesting only.
3. **Human‑in‑the‑loop "approval" in the pipeline is post‑hoc, not a gate.** The Deployment node auto‑writes `Strategy.status = "PaperTrading"`; `POST /agents/runs/{id}/approve` records agreement but changes nothing. Only the separate Paper→Live `promote` endpoint is a real RBAC gate (satisfies Business Rule 3; diverges from the Deployment Agent spec).
4. **Several specified agents are real but not wired into the research graph** — News, Sentiment, and Portfolio Manager run only as standalone scheduled jobs, so their signal never actually reaches strategy generation.
5. **Data/infra realities blunt the agents' trust.** Dev market data is ~2 years stale (the freshness gate would reject a real run today); the SEBI regulatory feed is confirmed impossible; the ML/RL platform (AGT‑017/018/019) was built then removed; a handful of skills still raise `SkillNotImplementedError`.

### Top 10 problems

1. **No unbroken end‑to‑end live graph run has ever completed** (REL‑005 exit criterion still open). This is the single headline proof of "genuinely autonomous" and it is unmet. *(Architectural Risk / High)*
2. **HITL approval is a post‑hoc annotation, not a gate** — Deployment node auto‑promotes to PaperTrading before any human is involved. *(Bug vs. Deployment Agent spec / High)*
3. **News, Sentiment, Portfolio Manager agents are not in the research graph** — real code, zero influence on strategy generation in production. *(Agent‑First Gap / Medium‑High)*
4. **Market data in the running environment is ~2 years stale**; `require_fresh()` would reject a real backtest today (REL‑028 finding). *(Bug / High for any real use)*
5. **Options Strategy Agent happy path proven only after repeated prompt fixes and only against live Zerodha prod** (no sandbox); no continuous exercise; F&O generation not confirmed to happen in normal production runs. *(Architectural Risk / Medium)*
6. **`SkillNotImplementedError` skills still in place** — `fetch_global_indices`, `query_macro_calendar` (CEO/Market Analyst context is thinner than the spec). *(Partial / Medium)*
7. **CI `pytest` is not green on a clean checkout** — needs data seeding; 4–6 persistent env failures (Zerodha daily‑token expiry). *(Architectural Risk / Medium)*
8. **MFA is disabled** for the three mandatory roles (accepted, but a live‑trading blocker). *(Risk / Medium)*
9. **Single Dev = Production host, no staging** (Phase 1 ADR 10). Accepted, but concentrates blast radius for a system meant to hold live capital. *(Architectural Risk / Medium)*
10. **Stale UI/console copy and docstrings** — `agents/page.tsx` still says "5 real nodes … placeholder terminal node"; `memory_agent.py` docstring says "no scheduler exists yet." *(Bug / Low, but erodes trust in the console as a source of truth)*

### Biggest concerns, one line each

- **Architecture:** the research graph is sound, but the *non‑graph* agents (news/sentiment/portfolio/omni‑channel) form a second, loosely‑coupled tier whose outputs never re‑enter the pipeline — the "organisation of agents" is really "one pipeline + some cron jobs."
- **Product:** the SRS promises a *closed‑loop, self‑improving autonomous quant firm*; what exists is a strong **research assistant** that proposes paper strategies for humans, with the learning loop (memory ingestion on failure) wired but lightly exercised.
- **Agent Console:** it faithfully shows *what the orchestrator did*, but its copy is stale, its HITL controls imply a gate that isn't there, and it has no view of the non‑graph agents' actual activity.

### Overall recommendation

**Incremental improvement is the right call — do not rewrite.** The foundation (LangGraph, LLM router, sandbox, risk engine, audit chain, RBAC, scheduler, dashboards) is real and well‑tested. Prioritise: (P0) achieve one real unbroken end‑to‑end run; make HITL a real gate; refresh market data. (P1) fold News/Sentiment into the graph; finish the stubbed skills; green CI. (P2) console/doc truthfulness pass; per‑agent observability for the non‑graph tier.

# 2. Original Product Vision (from the documentation only)

From `TradingOS_Master_Blueprint.md` §"Executive Summary"/SRS §1–2 and `Phase_4_AI_Agent_Design.md`:

> TradingOS is a **closed‑loop, self‑improving Enterprise AI Trading Operating System** for the Indian market (NSE/BSE) — "a fully autonomous organization of AI agents" that performs **end‑to‑end quantitative research, strategy generation, backtesting, paper trading, risk evaluation, and live execution**, learning continuously from successes and failures via a vector memory.

Pillars the docs commit to:

- **Agent‑first / OpenClaw‑inspired** (`Phase_4` §0): agents load modular **Skills** from a `SkillRegistry` at runtime; admins grant/revoke skills per agent; messaging‑first interaction (Telegram/Discord/WhatsApp/Slack) to a **CEO Agent**; "Live Canvas" in the web UI.
- **LangGraph orchestration** of **"over 30 specialized agents"** (Blueprint §1; `Phase_4` specifies **AGT‑001…AGT‑025**, with the remainder implemented as Skills).
- **Closed loop:** Research → Strategy → Code → Validate → Backtest → Evaluate → Optimize → Risk → Deploy(Paper) → (human) → Live; failures feed Qdrant memory to avoid repetition.
- **Hardcoded risk supremacy:** a non‑AI Risk Engine with a Max‑Drawdown Kill Switch has *final veto* over any AI decision (SRS Business Rule 1; `Phase_6` §4).
- **Human‑in‑the‑loop for live capital only** (SRS Business Rule 3): Paper→Live requires explicit human approval in the dashboard; the CEO Agent may only *recommend*.
- **Enterprise NFRs:** backtest < 5 s (NFR‑01), signal→broker < 50 ms (NFR‑02), 99.99% market‑hours uptime (NFR‑03), Vault‑managed secrets (NFR‑04), 100% LLM calls traced (NFR‑05), immutable audit log (BR‑05).
- **Stack (ADRs 1–9):** LangGraph+Pydantic v2, LiteLLM multi‑provider, Qdrant, Temporal, Polars+DuckDB, FastAPI, Postgres, custom `BrokerAdapter` (Zerodha+Upstox), VectorBT, HashiCorp Vault, Prometheus/Grafana/LangSmith, Docker/K8s.
- **Frontend (`Phase_7`):** dark "Bloomberg‑terminal‑of‑the‑AI‑era" with an **Agent Console** (live LangGraph viz + LangSmith "Thought Stream" + prompt hot‑swap), Risk Command Center + slide‑to‑confirm Kill Switch, Strategy Kanban, Live Canvas, RBAC.

# 9. Workflow Comparison (Required vs. Actual)

### Workflow 1 — Autonomous Strategy Generation & Deployment (SRS §8)

**Required:** Scheduler (6 AM IST) → CEO `ResearchDirective` → Market Analyst + **News + Sentiment** → Strategy Generator (RAG) → Code Gen ⇄ Validator (3×) → **Compliance** → Backtest → Evaluator (Sharpe>1.5) ⇄ Strategy Gen (feedback; 5→escalate CEO) → Optimization (WFO+MC) → Risk Manager → Deployment → **Paper**; on failure → memory ingest.

**Actual (`graph.py` + nodes):**
`ceo_agent → market_analyst → strategy_generator → options_strategy_agent → python_code_generator → compliance → python_validator ⇄ python_code_generator (3×) → backtesting → evaluator → [PASS] optimization → risk_manager → deployment → END` ; `[FAIL] → memory_ingest → strategy_generator` (or `→ ceo_agent` after 5).

**Where it diverges / breaks:**
1. **News + Sentiment are absent from this path.** `market_analyst_node` calls `fetch_india_vix`/`fetch_nse_sector_data` (real) but **not** the News/Sentiment agents; `strategy_generator_node` never reads `SentimentReport`. Those agents run only on their own schedule and write to a `news_sentiment` Qdrant collection that the generator does not query. → **Agent‑First Gap.**
2. **`fetch_global_indices` and `query_macro_calendar` raise `SkillNotImplementedError`** → CEO and Market Analyst run with thinner context than spec (`market_analyst.py` handles this gracefully; still a gap).
3. **The run has never completed unbroken end‑to‑end live** — free LLM providers (HuggingFace credits / OpenCode billing / Ollama timeouts) exhaust mid‑run; `_execute_graph_run` correctly marks the root run `Failed`. 5 of 10 nodes proven zero‑mock live; all 13 proven via mocked‑LLM unit tests (roadmap REL‑005 exit criterion, still `[ ]`).
4. **Deployment → Paper is not human‑gated.** `deployment_node` returns a recommendation; `_persist_strategy_progress` writes `Strategy.status="PaperTrading"`. Human `approve` is a later, optional annotation. Spec (`Phase_4` §12): *"execute the promotion only after explicit human approval is recorded."*
5. **Data Freshness gate** in `backtesting_node` calls `require_fresh(lake, universe, as_of=date.today())` — in the current environment this **raises** for every ingested symbol (data ends ~2024‑07‑19). So a real scheduled run today fails at the Backtesting node regardless of LLM availability.
6. **Optimization** Monte Carlo in the graph path resamples the *daily equity curve*, not per‑trade P&L (the direct‑API path uses real per‑trade via REL‑023). Documented, coarser.

### Workflow 2 — Live Market Execution (SRS §8)

**Required:** tick → strategy signal → Risk Manager check → Broker Agent → BrokerAdapter → Zerodha/Upstox → Order ID → Postgres.

**Actual:** `src/engine/live/execution_pipeline.py` implements tick → `SymbolState` (deque) → `pre_trade_checks` (compliance + risk) → `execution_agent` → `broker_adapter`. Dispatch latency p95 ~0.25–0.48 ms (real, Upstox sandbox). **But:** (a) no continuous tick producer runs (`tick_publisher` polls quotes every 5 s only during market hours; had a real bug where `list_symbols()` returned `[]`, fixed REL‑016); (b) **nothing auto‑calls `place_order`** — verified by repeated grep in the roadmap; (c) the pipeline does not persist `Order` rows (REL‑061). So this workflow is *code‑complete and latency‑proven* but **not an operating autonomous path** — by explicit, permanent design.

### Workflow 3 — "Analyze my portfolio, find highest‑risk positions" (example from the audit prompt)

**Required (agent‑first):** user → Portfolio Analysis Agent → portfolio data → position/risk analysis → (Risk Agent) → findings → store → display → audit.

**Actual:** There is **no conversational portfolio‑analysis agent path.** The user would use: the Portfolio & Risk Command Center dashboard (`/`) which reads `/portfolio/risk-metrics` (server‑side computed, calls the live broker); or `/agents` to trigger a *research* run (unrelated). The `ceo_agent_chat` persona (`src/api/routers/chat.py`) can converse but is not tool‑equipped to introspect positions and rank risk. → **Agent‑First Gap** for ad‑hoc analytical questions.

### Workflow 4 — Omni‑channel "request ad‑hoc research" (Blueprint §0)

**Required:** Telegram/Discord/Slack message → Notification Agent normalises → verify IAM role → CEO Agent → formatted reply.

**Actual:** `POST /webhooks/{telegram|discord|slack}` → signature verify → `_resolve_sender()` (maps `chat_id` to a verified `NOTIFICATION_CHANNELS` row; unmapped senders are recorded but **not routed**) → `ChatMessage` pair → detached‑thread LLM reply → `send_*_message`. Outbound **live‑verified** for all three (real Slack bot, 2 confirmed messages). **Inbound is only exercised via synthetic signed requests** — no public URL/tunnel in the dev environment, so a genuine Telegram‑originated message has never traversed it. Also: the reply path is the *chat* persona, which cannot *trigger a research run* — "request ad‑hoc research" over chat is not actually wired to `trigger_research()`.

# 13. Bugs

> No runtime execution was performed. These are code‑level or documented‑runtime findings. Severity per the requested scale.

> **Status update (2026-09-11, feature `001-ceo-led-trading-org`)**: BUG-A through BUG-I below are all closed by this feature's implementation — see `specs/001-ceo-led-trading-org/tasks.md` for the exact task and delivery note behind each. `BUG-C`'s underlying gap (real per-agent handler binding for market/news/sentiment/portfolio) was closed later than originally planned, as task **T113** during the Polish phase, after being re-deferred across three user stories (T036 → T055 → T077) without landing — see that task's note for the full account. `strategy_research` (the composite research sub-graph capability), the one piece BUG-C's fix left as a placeholder, is now also real — closed as **T113b** — see `docs/orchestration-overview.md` §6 for the full account, including a real datetime-validation bug found and fixed live while building it.

### High

**BUG‑A — Autonomous research run cannot complete in the current environment (data freshness).**
- **Finding:** `backtesting_node` calls `require_fresh(lake, universe, as_of=date.today())`; the dev data lake's latest bar is ~2024‑07‑19. Any scheduled/triggered run reaching Backtesting raises and the root run is marked `Failed`.
- **Expected:** SRS Workflow 1 completes CEO→Deployment autonomously.
- **Actual:** Blocked at Backtesting (independent of the separately‑documented LLM‑credit exhaustion).
- **Evidence:** `src/agents/nodes/backtesting.py:44‑52`; roadmap REL‑028 §"two real, honest constraints."
- **Impact:** The headline autonomous workflow is non‑functional in the running system.
- **Severity:** High. **Root cause:** one‑time historical backfill, no continuous EOD ingestion; scheduler's freshness pre‑check would also defer the daily cycle.
- **Recommendation:** Wire a real recurring EOD ingestion job (the bhavcopy provider from REL‑091..094 exists) or, for demo, seed rolling synthetic data via `ParquetLakeWriter`; add a "data age" panel to the console.
- **Status: RESOLVED (US7, T085–T090)** — `src/orchestration/freshness.py` makes dataset freshness a first-class organisational fact (real ingestion-result recording, cadence-window checks, no synthetic backfill); the task engine blocks a dataset-dependent task rather than running it against stale data (`DataStaleError`), and the console/attention queue surface staleness rather than hiding it.

**BUG‑B — HITL "approval" does not gate deployment (state‑integrity / false completion).**
- **Finding:** `deployment_node` output flows into `_persist_strategy_progress`, which writes `Strategy.status="PaperTrading"`. `POST /agents/runs/{id}/approve` sets `human_decision="Approved"` and commits — no state change. The UI presents Approve/Reject as if gating.
- **Expected:** `Phase_4` §12 — promotion executes *only after* explicit human approval is recorded.
- **Actual:** Strategy is already in Paper before any human acts; Approve is cosmetic; Reject downgrades to `Deprecated`.
- **Evidence:** `src/api/routers/agents.py:1824‑1915` (docstrings state this outright); `_persist_strategy_progress` (`agents.py:403+`).
- **Impact:** Operators may believe they authorised a transition they only rubber‑stamped; audit trail shows "approved" for an automatic action.
- **Severity:** High (semantic/compliance), Medium (functional — Paper is reversible).
- **Recommendation:** Either (a) add a real `AwaitingApproval` status: Deployment node writes `status="PendingPaper"`, and `approve` performs the transition; or (b) relabel the UI/endpoint as "acknowledge recommendation" and document that Backtesting→Paper is intentionally automatic.
- **Status: RESOLVED (US3, T045–T050)** — option (a): a deployment recommendation now writes `Strategy.status="PendingPaperApproval"` (never `PaperTrading`) and opens a real `ApprovalRequest`; only `POST /organization/approvals/{id}/approve` (SystemAdministrator/PortfolioManager only) performs the transition, with no timeout auto-resolution. The old no-op `approve_run`/`reject_run` handlers this finding names were removed.
- **Reopened (2026-09-12, `002-agent-organization-hardening` audit)**: the fix above closed the deployment-recommendation path specifically, but `POST /api/v1/strategies/{id}/promote` (a separate endpoint, same `SystemAdministrator`/`PortfolioManager` roles) accepted `to_status="PaperTrading"` for any strategy with a code version outside `Ideation` with **no reference to `ApprovalRequest` state at all** — a strategy just rejected (now `Deprecated`) could still be promoted straight into Paper Trading through this one endpoint, recreating BUG-B's exact "false completion" pattern one endpoint over.
- **Status: RE-RESOLVED (spec `002-agent-organization-hardening`, US1, T001–T005)** — `has_approved_paper_request(session, strategy_id)` (`src/orchestration/approvals.py`) requires the strategy's most-recently-created `ApprovalRequest` to be `approved`; `promote_strategy` now returns `409` for `to_status="PaperTrading"` unless that holds. `tests/integration/test_org_approval_bypass_closed.py` includes a genuine negative control: the guard was manually reverted, the exploit was confirmed to succeed, then the guard was restored and confirmed to block it — not merely a green test written after the fix. `approval.requested` (previously never emitted — only `approval.approved`/`approval.rejected` reached the event bus) now emits too.

### Medium

**BUG‑C — News/Sentiment/Portfolio‑Manager agents produce output no production path consumes (agent‑first gap).**
- **Finding:** `news_agent`/`sentiment_agent` write to a `news_sentiment` Qdrant collection; `market_analyst_node`/`strategy_generator_node` never query it. `portfolio_manager_agent` is `registry_only`, not scheduled, not in any graph — only reachable via `/portfolio/allocation-recommendation`.
- **Expected:** SRS Workflow 1 step 2 ("Market Analyst & News Agents analyze…"); AGT‑014 output "enriches the Market Analyst's MarketContext and the Strategy Generator's ideation."
- **Actual:** No enrichment occurs in a run.
- **Evidence:** `src/agents/nodes/market_analyst.py` (no news/sentiment calls); `src/agents/scheduler.py` (news/sentiment run standalone); `control.py` (portfolio_manager `enforced=False`).
- **Impact:** Strategy generation is blind to news/sentiment despite the agents existing.
- **Severity:** Medium‑High (Agent‑First Gap).

# 15. Architecture Audit (current)

**Backend (`src/`):** clean DDD‑ish layout matching `Phase_3` §1 (`api/ core/ agents/ engine/ data/ brokers/ models/ memory/ workers/ observability/ tui/`). Real polyglot persistence with strict module ownership (Postgres = `models/`+`core/db.py`; DuckDB/Parquet = `data/datalake/`; Qdrant = `memory/`; Redis = `engine/live/`).

# 17. Agent‑First Compliance Assessment

> **Does the current application actually satisfy the requirement that TradingOS tasks are performed through agents?**

**Partially — strong for research, weak or absent for several other meaningful workflows.**

**Where it genuinely is agent‑first (evidence):**
- Strategy research/generation/coding/validation/backtesting/optimization/risk‑assessment/deployment‑recommendation is executed by the LangGraph pipeline, not by manual UI operations. `POST /agents/research/trigger` and the scheduler are the entry points; `graph.stream()` runs the nodes; results persist and stream to the console. No dashboard button "writes a strategy" by hand.
- Failure learning is agent‑wired: every FAIL routes through `memory_ingest_node` → Qdrant → next Strategy Generator pass.
- Human‑suggested strategy changes run through a real second agent sub‑graph (`build_suggestion_regeneration_graph`), not a manual edit.
- Compliance and risk vetoes are real agent/engine gates in the pipeline.
- Omni‑channel chat routes to an LLM agent persona.

**Where it is not agent‑first (Agent‑First Gaps):**
1. **News & sentiment analysis** — agents exist but do not feed strategy generation; the workflow "Market Analyst & News Agents analyze cues" (SRS W1) does not happen in a run. *(BUG‑C)*
2. **Portfolio allocation** — `portfolio_manager_agent` is not scheduled or in any graph; allocation recommendations only appear if a human calls `/portfolio/allocation-recommendation`. The intended "rebalances weekly / on risk event" cadence is not wired.
3. **Ad‑hoc analytical questions** ("analyze my portfolio's risk", "why did this strategy draw down") — no tool‑equipped agent; only dashboards + non‑tool chat.
4. **Live execution** — deliberately manual/absent by the project's absolute constraint. This is defensible risk posture but means the SRS's "execute live trades" agent workflow is not realised.
5. **Deployment approval** — the human step is a post‑hoc annotation, not an agent‑mediated approval queue.
6. **Data ingestion trigger** — the Data Ingestion Agent exists, but in the current environment EOD data is not being ingested on a schedule (stale lake), so the agent‑driven freshness workflow is effectively dormant.
7. **Model lifecycle (ML/RL)** — removed entirely.

**Manual workflows that the docs say an agent should perform → flag as Agent‑First Gaps:** news/sentiment enrichment (C‑3/BUG‑C), allocation rebalancing, EOD ingestion scheduling, ad‑hoc portfolio analysis.

**Non‑functional agents:** none are outright fake, but **News, Sentiment, Portfolio Manager** are *effectively non‑functional in context* — they execute but influence nothing. **7 agents** (`execution_agent`, `portfolio_manager_agent`, `audit_agent`, `notification_agent`, `skill_registry_manager_agent`, `scheduler_agent`, `ceo_agent_chat`) have `enforced=False` control state — the toggle is real but no code checks it.

**Agent Orchestration Gap:** yes — orchestration exists *within* the research graph but not *across* the agent population. There is no mechanism by which the CEO Agent dynamically assigns work to News/Sentiment/Portfolio Manager and consumes their results.

**Execution Capability Gap:** the pipeline agents *do* execute real actions (run backtests, write DB rows, veto, recommend). The one true execution gap is live order placement — intentionally so.

**False Completion / State Integrity Issue:** yes — the Deployment→Paper transition + no‑op Approve (BUG‑B) is a genuine instance: the UI reports an action as human‑approved/completed without a corresponding human‑gated backend transition.

# 25. Final Verdict

| Dimension | Score |
|---|---|
| **Product completeness** (vs. SRS vision) | **~62 / 100** |
| **Technical completeness** (in‑scope code exists & is tested) | **~80 / 100** |
| **Agent architecture maturity** | **3.5 / 5** |
| **Agent‑first compliance** | **~65 / 100** |
| **Production readiness** | **~45 / 100** |

### What is working
- Real LangGraph orchestration: 13‑node research pipeline + suggestion sub‑graph, retry loops, escalation, checkpointer‑backed pause/resume, per‑agent halt‑on‑entry control.
- Real multi‑provider LLM routing with fallback chains and a spend guard.
- Real deterministic engines: sandboxed vectorbt backtesting (NFR‑01 met on warm pool), Indian friction model, WFO/Monte Carlo/Optuna, hardcoded risk (position sizing, correlation, kill switch, naked‑options scanner), compliance checker with real Block authority.
- Real, strong auditability: SHA‑256 hash chain + Postgres trigger + non‑superuser app role + MinIO WORM archive + divergence monitor.
- Real security surface: Vault server + Transit ES256 JWT, Casbin RBAC, refresh‑token rotation, webhook signature verification, security headers, global rate limiter (MFA built but off).
- Real scheduler, real broker adapters + circuit breaker, real observability with market‑hours SLO + multi‑channel alerting, real omni‑channel outbound (Telegram/Discord/Slack).
- A comprehensive, genuinely tested frontend (10 authenticated routes) including a functional Agent Console, Strategy Kanban + Review Panel, Backtests dashboard, Paper Trading Desk, Orders monitoring, Audit view.
- Exceptionally honest internal documentation (roadmap + ERDTM) that this audit largely corroborates.

### What is not working
- **No unbroken end‑to‑end autonomous research run has ever completed** (blocked by LLM‑credit exhaustion *and* stale data).
- **HITL approval does not gate deployment** — Backtesting→Paper is automatic; Approve is an audit annotation.
- **News, Sentiment, Portfolio Manager agents influence nothing** in production — real code, no consumer.
- **Live/autonomous trading is absent by design** — no code path places an order; the live pipeline doesn't even persist orders.
- **Stale environment realities:** market data ~2 years old; MFA disabled; single host = prod; `main` unprotected; CI red on clean checkout; ML/RL platform removed; several skills stubbed; SEBI feed impossible.
- **Console/doc drift:** stale captions and docstrings misrepresent current state.

### What must be fixed first
1. Refresh market data + continuous EOD ingestion (BUG‑A / P0‑2).
2. Fund one reliable LLM provider and record ≥5 consecutive unbroken autonomous cycles (P0‑1).
3. Make HITL a real gate (`PendingPaper` status) or relabel it honestly (BUG‑B / P0‑3).

### Can the current architecture support the TradingOS vision?
**Yes, for the research/backtesting/paper half — with incremental work, not a rewrite.** The LangGraph + LLM‑router + sandbox + risk‑engine + audit foundation is real and extensible. The autonomous‑*trading* half of the vision is deliberately excluded by an absolute project constraint and would require a separate, explicitly‑governed decision to build.

### Is incremental improvement practical?
**Yes.** Every P0/P1 item is a bounded change against working code. The biggest single lever is proving one real end‑to‑end run — most integration risk is hiding in the fact that it has never happened.

### Are major architectural changes required?
**No.** The ADRs' choices (LangGraph, single‑host, LiteLLM, Qdrant, hardcoded risk supremacy, human‑gated live capital) are sound and should be preserved. The needed changes are: fold the second agent tier into the orchestrator, make HITL real, keep data fresh, and tell the truth in the console.
